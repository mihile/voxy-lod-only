# 구조물 로그 스팸 개선 — 0.8.0+1.20.1

2026-10-13. 실행 중인 Prominence 4.1.3 서버는 읽기만 했으며,
별도 테스트 서버에서 검증했습니다. 운영 JAR, 설정, 월드, 캐시를 교체하거나 이동하지 않았습니다.

## 원인과 변경

BetterArcheology의 catacombs/light_temple 템플릿 25개에는 `pool`과 `target`이
모두 `minecraft:`인 종료 연결 26개가 있습니다. 레지스트리에 이 풀은 없어
Minecraft의 jigsaw 조립기가 연결을 검사할 때마다 경고를 반복합니다.
`pool`만 `minecraft:empty`로 보정합니다. 철창, 썩은 나무, 공기 등 `final_state`와
그 밖의 NBT, 블록, 좌표는 유지합니다.

Integrated Villages에는 설치되지 않은 `quark:glass_frame` 134개와
`guardvillagers:guard` 12개의 선택적 엔티티 참조가 있습니다. 해당 네임스페이스의
이 두 종류만 실제 레지스트리에 없을 때 제외합니다. 등록된 엔티티는 유지합니다.

LOD 미리보기에서는 구조물 엔티티 생성·역직렬화 자체를 건너뜁니다.
GenerationGuard 밖의 일반 월드 엔티티 배치는 유지합니다.
다른 모드의 엔티티 처리도 포함하도록 `placeEntities` 전체를 WrapMethod로 감쌉니다.

ModernFix가 `loadFromResource`를 교체하므로, 보정은 그 바깥 `tryLoad`의 반환 시점,
공유 템플릿 캐시에 들어가기 전에 수행합니다. 확인된 템플릿 데이터만 메모리에서
보정하며 원본 모드/데이터팩을 다시 쓰거나 로그를 필터링하지 않습니다.
캐시 재로딩으로 같은 템플릿이 다시 처리되면 상태 카운터는 다시 증가할 수 있습니다.

변경한 주요 파일:

- `StructureCompatibility.java`: 알려진 참조 보정과 처리 카운터.
- `TemplateAccess.java`, `mixin/StructureTemplateMixin.java`: 템플릿 접근과 LOD 엔티티 생략.
- `mixin/StructureTemplateManagerMixin.java`: 캐시 게시 전 보정.
- `LodOnlyManager.java`: status에 세 카운터 표시.
- mixin 등록, 버전, README/DESIGN, 단위 검사와 별도 검증 도구.

Voxy 본체와 VoxyServer의 제품 코드는 이번 수정에서 변경하지 않았습니다.

## 클라이언트 연동과 남은 제한

`build/activity-20261013-194938`에서 최종 JAR로 기능 검사를 수행했습니다.
클라이언트에는 LOD Only를 설치하지 않았습니다. 프로토콜 2 연결, 원거리
127,248개 non-air voxel 수신과 렌더러 활성 상태, 일반 원거리 청크 부재,
설정 재적용, 재접속 시 9청크의 단일 완료, 자동→수동 작업 전환과 빠른 접속 해제,
빈 서버의 초당 4청크 제한과 정상 종료를 확인했습니다.
클라이언트/서버/재시작 서버 모두 종료 코드 0이며 UNKNOWN/Network handle null은 없습니다.
전체 Prominence 클라이언트의 셰이더 화면이나 FPS 검사는 아닙니다.

그러나 이 마지막 실행에서는 설치된 VoxyServer port.1 클라이언트가 해시 보조 파일의
임시 파일을 교체할 때 AccessDeniedException을 세 번 기록했습니다. 기능 검사만
통과한 것이므로 결과를 `FUNCTIONAL_PASS_WITH_CLIENT_HASH_IO_ERRORS`로 구분했습니다.
종료 후 `.bin`은 유효한 803개 항목, 남은 `.bin.tmp`는 유효한 1,102개 항목입니다.
이를 LOD 저장 데이터 소실로 단정하지 않으며, 해시 인덱스의 최종 저장은 불완전합니다.
설치 JAR의 입력 스트림 close도 확인했지만 파일을 잠근 주체는 확인하지 못했습니다.
이 문제는 VoxyServer 클라이언트 저장 경로의 별도 수정/검증 대상으로 남깁니다.
두 파일을 삭제하거나 복구 목적으로 이동하지 않았습니다.

블록 엔티티 생성 전 접근 경고, Voxy 저장 큐의 INFO 메시지와 기존 모드팩 시작 오류도
이번 보정의 대상에 포함하지 않았고 숨기지 않았습니다. 속도/FPS 향상 수치를 주장하지 않습니다.

이 검증 시점에는 운영 서버의 기존 0.7 JAR을 유지했습니다. 이후 사용자가
0.8을 적용한 운영 환경에서 자동 반경 128의 생성 완료, 클라이언트 수신 기록 증가,
Voxy 렌더링 on/off에 따른 원거리 지형 표시를 확인했습니다.
클라이언트에 LOD Only를 추가할 필요는 없습니다.
